## Key Takeaways
1. **B+ 樹是 MySQL 索引的核心**：非葉節點不存資料（只存索引），相同磁碟塊能放更多索引項；葉節點以鏈結串列相連支援範圍查詢；3 層約可容納 ~17 億筆，極少磁碟 I/O——這是它勝過 B 樹、Hash、紅黑樹的關鍵。
2. **InnoDB 預設隔離級別是 Repeatable Read**，並透過 MVCC + Gap Lock 在 RR 級別就解決了幻讀（標準 SQL 需 Serializable 才解幻讀）。
3. **InnoDB vs MyISAM**：前者支援交易、行鎖、外鍵、崩潰自動恢復；後者表鎖、不支援交易與外鍵，但支援全文索引。
4. **索引概念**：聚簇索引（主鍵組織整行資料）、二級索引（存索引欄+主鍵，需回表）、覆蓋索引（查詢欄全在索引中免回表）、最左前綴原則（複合索引 `(a,b,c)` 只支援 a / a,b 起頭的查詢）。
5. **三大正規化**：1NF 原子性、2NF 完全依賴主鍵（消除部分依賴）、3NF 非主屬性直接依賴主鍵（消除遞移依賴）。
6. **Redis 為何快**：基於記憶體、單執行緒免去上下文切換與鎖競爭、epoll I/O 多路復用；瓶頸在記憶體頻寬而非 CPU，故單執行緒足矣。
7. **快取三大經典問題**：雪崩（大量 key 同時過期）、穿透（查不存在的資料繞過快取打 DB）、擊穿（單一熱點 key 過期瞬間高併發）——各有對應解法（隨機過期、布隆過濾器/快取空值、互斥鎖/熱點永不過期）。
8. **Redis 過期策略**：惰性刪除 + 定期刪除組合；記憶體淘汰以 `allkeys-lru` 最常用。
9. **快取與資料庫一致性**：推薦「先更新資料庫，再刪除快取」（Cache Aside），接受最終一致性與有界的不一致窗口。
