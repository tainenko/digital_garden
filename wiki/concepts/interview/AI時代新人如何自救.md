# AI 時代企業只招高級，新人如何自救

來自極海Channel（前阿里巴巴工程師）的觀察：2025-2026 年，大廠和中廠都在壓縮初級工程師的招聘名額，AI 可以生成代碼，「寫代碼」本身的門檻在降低，但「判斷什麼代碼值得寫」的門檻在提高。

> 「AI 時代，企業不是不需要工程師，是不需要『只會執行'的工程師。」

---

## 為什麼 AI 時代更難找工作

### 供給增加

```
以前：只有寫代碼的人會被招進來
現在：
- 非技術背景的人用 AI 也能做出原型
- 全球工程師市場，地域壁壘降低
- AI 自動生成的代碼不斷進化
→ 基礎工程師的競爭者大幅增加
```

### 需求結構改變

```
以前的招聘金字塔：
  資深/架構師    ← 少
  中級工程師     ← 中
  初級工程師     ← 多（大量招聘）

AI 時代的招聘金字塔：
  資深/架構師    ← 需求不變或增加
  中級工程師     ← 需求略減
  初級工程師     ← 需求大幅萎縮（AI 替代了大部分簡單任務）
```

企業算的是：1 個 Senior + AI 工具 = 3 個 Junior 的產出。
所以雇用 1 個 Senior > 雇用 3 個 Junior。

## 新人的生存路徑

### 路徑一：快速建立「專業縱深」

不要做樣樣通的通才，在一個方向上建立超越 AI 的深度：

```
舉例：後端工程師新人
❌ 錯誤路線：
  Java、Python、Go 都學一點
  各種框架都摸過
  沒有一樣真正深入

✅ 正確路線（以 Java 後端為例）：
  1. JVM 深度：GC 調優、類加載機制、JIT 編譯
  2. 並發深度：AQS 原理、鎖升級、ThreadLocal 內存洩漏
  3. 一個細分領域的實戰：
     例如「高並發訂單系統」或「實時推薦引擎」
     有可以拿出來說的真實數字（QPS、延遲、規模）
```

**AI 可以生成普通的 Java 代碼，但不能替代對 JVM 有深度理解的工程師在生產環境做調優。**

### 路徑二：成為「AI 的最佳搭檔」

不要跟 AI 競爭，讓 AI 成為你的杠桿：

```
同樣是完成一個功能：
普通新人：自己慢慢寫，3 天
用 AI 的普通新人：讓 AI 生成，1 天，但不理解代碼，也改不了 bug
善用 AI 的工程師：
  - 用 AI 快速搭架構（2 小時）
  - 自己審查代碼、識別問題（1 小時）
  - 用 AI 寫測試、補文件（1 小時）
  - 調優和踩坑（1 天）
  → 總時間：1.5 天，但質量遠高於普通新人
```

**會評估 AI 輸出品質的工程師，比不會的更值錢。**

### 路徑三：建立「可見度」

在 AI 時代，你需要讓別人知道你的存在：

```
可見度建設（按優先序）：
1. GitHub 開源項目：有真實 star 的項目
2. 技術博客/文章：一個月至少 1 篇深度文章
3. 社群貢獻：回答問題、提 PR 給知名開源項目
4. 競賽成績：算法競賽、黑客松
5. 業界認識的人：去 meetup、到處認識人
```

內部推薦仍然是最高效的求職方式，可見度是建立這種關係的前提。

## 面試中如何彌補「資歷不足」

### 策略一：用項目深度補工作年限

面試官問「你只有 1 年經驗，能勝任這個職位嗎？」

```
❌ 錯誤回答：
「我雖然經驗不多，但我學習很快...」

✅ 正確回答：
「我的工作年限是 1 年，但在這 1 年裡我做了：
[具體項目 A：規模、挑戰、解法、數字]
[具體項目 B：規模、挑戰、解法、數字]
我相信這些實際解決的問題，能代表我的技術能力。」
```

**用具體的「我解決了什麼問題」代替「我有多少年資歷」。**

### 策略二：展示「AI 協作能力」作為差異化

2025-2026 年，能高效使用 AI 工具是加分項：

```
在自我介紹中加入：
「我在工作中大量使用 AI 工具來提升效率。
例如在 X 項目中，我用 Claude Code 完成了架構搭建，
自己負責評審代碼品質和性能調優，
最終在 3 週內交付了通常需要 6 週的功能。」
```

### 策略三：針對中小型公司調整策略

大廠縮招，但中小公司的需求結構不同：

```
大廠：只招 Senior（AI 填補 Junior 的缺口）

成長期中小公司：
- 需要能「全棧」、「快速迭代」的工程師
- 更看重「執行力」而非「深度」
- 新人更容易被看見（不淹沒在大廠的人才庫中）
- 股票 Upside 可以補償薪資差距

初創公司：
- 需要「什麼都能做的人」
- 新人可以快速積累多樣化的項目經驗
- 風險：沒有導師體系，可能學到錯誤做法
```

## 新人的 6 個月自救計畫

```
Month 1-2：建立基礎深度
- 選定一個方向（Java 後端 / 前端 / 數據工程）
- 深入一個子主題（JVM / React 性能 / 資料管道）
- 輸出：一篇技術文章說清楚這個子主題

Month 3-4：做一個有質量的項目
- 目標：能在簡歷上寫出「日活 X 萬、QPS X 萬」的數字
- 用 AI 工具快速搭建，但自己真正理解每個部分
- 把踩坑過程記錄成文章

Month 5：建立可見度
- GitHub 開源這個項目
- 寫 3 篇關於這個項目技術細節的文章
- 聯繫 2-3 個做你想去的公司的工程師

Month 6：高效求職
- 用前 5 個月的積累定制簡歷
- 按「熱身 → 目標 → 夢想」順序投遞
- 每次面試後覆盤，更新技術知識漏洞
```

## 心態：焦慮沒有用，行動才有用

```
❌ 焦慮型行為：
- 刷各種「AI 會取代工程師嗎」的文章
- 到處問「現在學什麼最值錢」
- 一直換方向，沒有一樣做深

✅ 行動型策略：
- 每天進步 1% 的具體事情：今天讀了什麼、今天寫了什麼
- 設定 3 個月可衡量的里程碑
- 找 1 個比你強的工程師當 mentor（可以是網上的人，定期請教）
```
