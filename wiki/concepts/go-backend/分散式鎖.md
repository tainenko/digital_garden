# 分散式鎖

## 為什麼需要分散式鎖

單機環境的 `sync.Mutex` 只在同一個 process 有效。多個服務實例（K8s 多 Pod）同時操作同一個資源時，需要跨進程協調：

```
❌ 問題場景：
Pod A: 讀庫存 = 1 → 判斷「有庫存」
Pod B: 讀庫存 = 1 → 判斷「有庫存」
Pod A: 扣庫存 → 庫存 = 0
Pod B: 扣庫存 → 庫存 = -1 （超賣！）

✅ 用分散式鎖：
Pod A 取得鎖 → 讀庫存 = 1 → 扣庫存 → 釋放鎖
Pod B 等待鎖 → 取得鎖 → 讀庫存 = 0 → 返回「庫存不足」→ 釋放鎖
```

## 分散式鎖的三個必要條件

1. **互斥性**：同一時刻只有一個持有者
2. **無死鎖**：持有者崩潰後，鎖能自動釋放（TTL）
3. **安全釋放**：只有鎖的持有者能釋放它（不能釋放別人的鎖）

## Redis 實現（SETNX + Lua）

### 簡單實現

```go
package dlock

import (
    "context"
    "errors"
    "time"

    "github.com/google/uuid"
    "github.com/redis/go-redis/v9"
)

var ErrLockNotAcquired = errors.New("lock not acquired")

type RedisLock struct {
    client *redis.Client
    key    string
    value  string        // 唯一標識持有者，防止誤釋放
    ttl    time.Duration
}

func NewLock(client *redis.Client, key string, ttl time.Duration) *RedisLock {
    return &RedisLock{
        client: client,
        key:    "lock:" + key,
        value:  uuid.New().String(), // 每個鎖實例唯一
        ttl:    ttl,
    }
}

// Acquire 嘗試取得鎖（不等待）
func (l *RedisLock) Acquire(ctx context.Context) error {
    ok, err := l.client.SetNX(ctx, l.key, l.value, l.ttl).Result()
    if err != nil {
        return fmt.Errorf("acquire lock: %w", err)
    }
    if !ok {
        return ErrLockNotAcquired
    }
    return nil
}

// Release 釋放鎖（Lua 腳本確保原子性）
// 只有持有者才能釋放（用 value 驗證）
var releaseScript = redis.NewScript(`
    if redis.call("get", KEYS[1]) == ARGV[1] then
        return redis.call("del", KEYS[1])
    else
        return 0
    end
`)

func (l *RedisLock) Release(ctx context.Context) error {
    result, err := releaseScript.Run(ctx, l.client, []string{l.key}, l.value).Int()
    if err != nil {
        return fmt.Errorf("release lock: %w", err)
    }
    if result == 0 {
        // 鎖已過期或被其他持有者釋放
        return errors.New("lock was already released or expired")
    }
    return nil
}

// WithLock 是安全的封裝：自動取得和釋放
func WithLock(ctx context.Context, lock *RedisLock, fn func(ctx context.Context) error) error {
    if err := lock.Acquire(ctx); err != nil {
        return err
    }
    defer func() {
        if err := lock.Release(context.Background()); err != nil {
            log.Warnf("failed to release lock %s: %v", lock.key, err)
        }
    }()
    return fn(ctx)
}
```

### 帶重試的取鎖

```go
// AcquireWithRetry 自旋等待鎖
func (l *RedisLock) AcquireWithRetry(ctx context.Context, maxWait time.Duration) error {
    deadline := time.Now().Add(maxWait)
    backoff := 10 * time.Millisecond

    for time.Now().Before(deadline) {
        err := l.Acquire(ctx)
        if err == nil {
            return nil // 取鎖成功
        }
        if !errors.Is(err, ErrLockNotAcquired) {
            return err // 非競爭錯誤（Redis 連線問題）
        }

        // 加入隨機 jitter 避免鎖衝突（herd effect）
        jitter := time.Duration(rand.Intn(10)) * time.Millisecond
        select {
        case <-ctx.Done():
            return ctx.Err()
        case <-time.After(backoff + jitter):
        }

        if backoff < 200*time.Millisecond {
            backoff *= 2
        }
    }

    return fmt.Errorf("could not acquire lock within %v", maxWait)
}
```

### 鎖的自動續期（Watchdog）

如果業務操作時間超過 TTL，鎖會自動過期被其他人取走：

```go
type LockWithWatchdog struct {
    *RedisLock
    stopWatchdog chan struct{}
}

func (l *LockWithWatchdog) Acquire(ctx context.Context) error {
    if err := l.RedisLock.Acquire(ctx); err != nil {
        return err
    }

    // 啟動 watchdog goroutine
    l.stopWatchdog = make(chan struct{})
    go l.watchdog(ctx)
    return nil
}

func (l *LockWithWatchdog) watchdog(ctx context.Context) {
    // 在 TTL 過期前 1/3 時續期
    ticker := time.NewTicker(l.ttl / 3)
    defer ticker.Stop()

    for {
        select {
        case <-l.stopWatchdog:
            return
        case <-ctx.Done():
            return
        case <-ticker.C:
            renewScript := redis.NewScript(`
                if redis.call("get", KEYS[1]) == ARGV[1] then
                    return redis.call("pexpire", KEYS[1], ARGV[2])
                else
                    return 0
                end
            `)
            renewScript.Run(ctx, l.client, []string{l.key}, l.value, l.ttl.Milliseconds())
        }
    }
}

func (l *LockWithWatchdog) Release(ctx context.Context) error {
    close(l.stopWatchdog)
    return l.RedisLock.Release(ctx)
}
```

## Redlock（多節點 Redis）

單個 Redis 節點有 SPOF（單點故障）風險。Redlock 算法在多個獨立 Redis 節點上取鎖：

```go
import "github.com/go-redsync/redsync/v4"

// 建立連接到 N 個獨立 Redis 節點（非 Cluster）
pools := []goredis.Pool{
    pool1, pool2, pool3, // 至少 3 個，奇數
}
rs := redsync.New(pools...)

mutex := rs.NewMutex("critical-section",
    redsync.WithExpiry(10*time.Second),
    redsync.WithTries(5),
)

if err := mutex.Lock(); err != nil {
    // 取鎖失敗
}
defer mutex.Unlock()
```

**Redlock 規則**：在超過半數節點（N/2 + 1）取得鎖才算成功。即使一個節點掛掉，鎖依然安全。

## 實際應用場景

### 防止庫存超賣

```go
func (s *InventoryService) Reserve(ctx context.Context, productID string, quantity int) error {
    lock := dlock.NewLock(s.redis, "inventory:"+productID, 5*time.Second)

    return dlock.WithLock(ctx, lock, func(ctx context.Context) error {
        // 在鎖保護下：讀-判斷-寫 是原子的
        stock, err := s.repo.GetStock(ctx, productID)
        if err != nil {
            return err
        }
        if stock < quantity {
            return ErrInsufficientStock
        }
        return s.repo.DeductStock(ctx, productID, quantity)
    })
}
```

### 防止重複執行（Exactly-Once 任務）

```go
// 定時任務：確保多個實例中只有一個執行
func (s *Scheduler) RunDailyReport(ctx context.Context) error {
    today := time.Now().Format("2006-01-02")
    lock := dlock.NewLock(s.redis, "daily-report:"+today, 10*time.Minute)

    err := lock.Acquire(ctx)
    if errors.Is(err, dlock.ErrLockNotAcquired) {
        log.Info("daily report already running on another instance")
        return nil
    }
    if err != nil {
        return err
    }
    defer lock.Release(context.Background())

    return s.generateReport(ctx)
}
```

## 分散式鎖 vs 資料庫樂觀鎖

| 面向 | 分散式鎖（Redis）| 樂觀鎖（DB version）|
|------|----------------|-------------------|
| 實作複雜度 | 中 | 低 |
| 性能 | 高（Redis 快）| 中（DB 較慢）|
| 適合場景 | 高並發，鎖時間短（< 1s）| 衝突率低，可以重試 |
| 死鎖風險 | 低（TTL 自動過期）| 無 |
| 依賴 | 需要 Redis | 只需要 DB |

**樂觀鎖範例**：
```sql
-- 版本號樂觀鎖：更新時確認版本
UPDATE inventory
SET stock = stock - $1, version = version + 1
WHERE product_id = $2 AND version = $3
-- 如果 rows_affected = 0，表示有並發修改，需要重試
```
