# 系統設計核心技術棧

面試中需要知道「用什麼工具、為什麼用、什麼時候用」的核心技術，對應 [[RESHADED面試框架]] 中的 SLIC FAST 元件。

---

## Cache 層

### Redis
- **定位**: 記憶體 KV 存儲，支援多種資料結構（String / Hash / List / Set / Sorted Set）
- **使用場景**:
  - Session 存儲
  - 排行榜（Sorted Set）
  - 發布訂閱（Pub/Sub）
  - 分散式鎖
  - 計數器
- **快取策略**:
  | 策略 | 說明 | 適用 |
  |------|------|------|
  | Cache-Aside | 讀時 miss → 從 DB 填入 | 讀重系統 |
  | Write-Through | 寫 DB 同時更新 Cache | 讀寫均衡 |
  | Write-Behind | 先寫 Cache，非同步寫 DB | 寫重系統 |
  | TTL Eviction | 過期自動清除 | 時效性資料 |

## 訊息佇列

### Kafka
- **定位**: 分散式事件串流平台，高吞吐量、持久化
- **核心概念**: Topic / Partition / Consumer Group / Offset
- **使用場景**:
  - 事件驅動架構（服務解耦）
  - 日誌收集與分析
  - 即時資料管道
  - 削峰填谷（高頻寫入緩衝）
- **vs RabbitMQ**: Kafka 適合高吞吐+持久化；RabbitMQ 適合複雜路由+即時回應

### 訊息佇列模型
| 模型 | 說明 | 代表 |
|------|------|------|
| Message Queue（點對點） | 一個消息只被一個消費者處理 | RabbitMQ |
| Pub-Sub（發布訂閱） | 一個消息廣播給所有訂閱者 | Kafka / Google Pub/Sub |

---

## 搜尋

### Elasticsearch
- **定位**: 基於 Lucene 的分散式搜尋引擎
- **使用場景**:
  - 全文搜尋
  - 日誌分析（ELK Stack）
  - 複雜過濾查詢
- **注意**: 不適合作為主資料庫，通常與 DB 並用（DB 為主，ES 為搜尋副本）

---

## 資料庫

### 關聯式（SQL）
- PostgreSQL / MySQL
- ACID 事務、複雜查詢、結構固定
- 適合：金融、訂單、用戶帳號

### 非關聯式（NoSQL）
| 類型 | 代表 | 適用 |
|------|------|------|
| KV Store | DynamoDB、Redis | Session、短網址、設定檔 |
| 文件型 | MongoDB | 半結構化資料、商品目錄 |
| 寬欄型 | Cassandra、HBase | 時序資料、超大規模寫入 |
| 圖型 | Neo4j | 社交關係、推薦系統 |

### Object Storage
- AWS S3 / GCS
- 適合：圖片、影片、文件（Blob）
- **重要**：大型二進位檔案不放 DB，放 Object Storage，DB 只存 URL

---

## 負載均衡與 CDN

### Load Balancer
- 演算法：Round Robin / Least Connections / IP Hash / Weighted
- 健康檢查：定期 ping 後端，自動移除不健康節點
- Layer 4（TCP）vs Layer 7（HTTP）：L7 可根據路徑/Header 路由

### CDN
- 靜態資源（圖片/JS/CSS/影片）放邊緣節點
- 降低源站負載、減少跨區延遲
- Pull vs Push 模式

---

## 即時通訊

| 方案 | 適用場景 | 特性 |
|------|---------|------|
| Polling | 不重要的低頻更新 | 實作簡單，浪費頻寬 |
| Long Polling | 低延遲通知 | 伺服器保持連線直到有資料 |
| WebSocket | 即時雙向通訊（聊天、遊戲） | 持久連線，低延遲 |
| SSE（Server-Sent Events） | 單向推播（通知、Feed更新） | 比 WebSocket 輕量 |

## 面試使用指南

選技術時說清楚 **為什麼**，不要只說「我用 Redis」：

> ❌「我用 Redis 來做快取。」
> ✅「因為是讀重系統，P99 延遲要求 <100ms，我用 Redis Cache-Aside 策略把熱點資料放記憶體，命中率預計 95%+，可以大幅減少 DB 壓力。」
