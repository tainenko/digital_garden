# 分散式任務排程系統

## 需求定義

**功能需求：**
- 在指定時間點提交並執行任務（一次性 / 週期性）
- 跨工作節點分散式執行
- 追蹤執行狀態與資源使用

**非功能需求：**
- 可靠性：任務至少執行一次（at-least-once）
- 水平擴展：支援百萬級日任務量
- 容錯：失敗自動重試，避免重複執行
- 冪等性：重試時不產生副作用

---

## 容量估算

- **任務量**：34,722 tasks/min（約 5 億 tasks/day）
- **元資料**：~1 GB/day
- **網路頻寬**：~1 MB/s

---

## 資料庫設計（Cassandra）

Cassandra 適合此場景：分散式、高寫入、可按時間分區

```
jobs 表（partition: user_id, sort: job_id）
  job_id, user_id, name, schedule_expr, status, created_at

task_schedule 表（partition: minute-level UNIX timestamp）
  scheduled_minute, job_id, task_id
  ← 按分鐘分區，Scheduler 只需查「下一分鐘」的 tasks

task_execution_history 表（partition: job_id）
  job_id, task_id, started_at, finished_at, status, result
```

---

## 核心架構

```
[任務提交 API]
      ↓
[Task_Schedule 表]
      ↓ (Scheduler 每分鐘掃描)
[Message Broker（多層佇列）]
      ↓
[Executor 集群]
      ↓
[Task_Execution_History 表]
```

**為什麼用 Message Broker 而非 Load Balancer？**
- Load Balancer 需要感知所有 Executor 完整狀態
- Message Broker 解耦分配，長短任務不互相阻塞
- 支援多優先級佇列（高優先任務不被低優任務拖慢）

---

## 容錯機制

| 組件 | 容錯方式 |
|------|---------|
| Scheduler | 多副本 + Leader Election（ZooKeeper） |
| Message Broker | Broker 複製（Kafka min.insync.replicas）|
| Executor | 任務執行前獲取分散式鎖（ZooKeeper + TTL）|
| 冪等性 | 每個 task_id 唯一，重試前檢查 execution_history |

## DelayQueue 單機輕量實作

適用場景：無需分散式的小規模排程（如 JVM 內部任務）

```python
import heapq, time, threading

class DelayQueue:
    def __init__(self):
        self._queue = []
        self._lock = threading.Lock()

    def push(self, task, delay_sec):
        execute_at = time.time() + delay_sec
        with self._lock:
            heapq.heappush(self._queue, (execute_at, task))

    def pop_ready(self):
        now = time.time()
        with self._lock:
            ready = []
            while self._queue and self._queue[0][0] <= now:
                _, task = heapq.heappop(self._queue)
                ready.append(task)
            return ready
```

## 與 Cron 的差異

| 面向 | Cron | 分散式任務排程 |
|------|------|-------------|
| 規模 | 單機 | 多節點水平擴展 |
| 容錯 | 無 | Leader Election + 重試 |
| 冪等性 | 不保證 | 分散式鎖保障 |
| 狀態追蹤 | 無 | 完整 execution history |
