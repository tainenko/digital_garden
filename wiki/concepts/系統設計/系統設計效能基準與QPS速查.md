# 系統設計效能基準與QPS速查

面試估算常用的組件吞吐量基準，搭配 [[Back-of-the-Envelope 估算]] 使用。

> 注意：以下數字為**量級參考**，實際值視硬體規格、查詢複雜度、網路環境而異。

---

## 組件 QPS 基準

| 組件 | 典型 QPS | 備注 |
|------|---------|------|
| **Nginx** | ~300,000 | 靜態文件服務 |
| **Redis** | 10,000 – 100,000 | 單線程，讀寫均高；集群可線性擴展 |
| **MySQL** | 讀：數十萬；寫：~100,000 | 讀可用 Read Replica 擴展；寫受 ACID 限制 |
| **Tomcat** | ~20,000 | Java Servlet 容器，CPU bound |
| **Kafka** | 百萬級 msg/s | 磁碟順序寫入，延遲 < 10ms |
| **Elasticsearch** | 萬–十萬/s | 依索引大小與查詢複雜度 |
| **PostgreSQL** | 讀：數十萬；寫：~數萬 | 視查詢與連接池 |

---

## 流量指標定義

| 指標 | 全稱 | 說明 |
|------|------|------|
| **PV** | Page View | 頁面瀏覽次數（每次加載計一次）|
| **UV** | Unique Visitor | 獨立訪客數（去重）|
| **IP** | 獨立 IP 數 | 按 IP 去重的訪問來源 |
| **DAU** | Daily Active Users | 日活躍用戶 |
| **MAU** | Monthly Active Users | 月活躍用戶 |
| **QPS** | Queries Per Second | 每秒查詢數 |
| **TPS** | Transactions Per Second | 每秒事務數（含多次操作）|

---

## 估算公式速查

```
峰值 QPS ≈ 平均 QPS × 2–3 倍
平均 QPS = DAU × 平均每日請求次數 / 86,400

儲存量（每日）= 寫入 QPS × 每條資料大小 × 86,400

讀寫比：社群媒體 100:1；DB 一般 10:1
```

---

## 記憶體估算基準

| 資料類型 | 典型大小 |
|---------|---------|
| 一則 Tweet | ~300 bytes |
| 一則 IM 訊息 | ~100 bytes |
| 一張縮圖 | ~200 KB |
| 一張高清圖 | ~1–5 MB |
| 一分鐘影片（1080p） | ~50–100 MB |

---

## 延遲參考值

| 操作 | 延遲量級 |
|------|---------|
| L1 Cache 命中 | 0.5 ns |
| RAM 存取 | 100 ns |
| SSD 隨機讀取 | 100 µs |
| 磁碟 HDD 讀取 | 10 ms |
| 同機房網路往返 | 0.5 ms |
| 跨洲網路往返 | 150 ms |
