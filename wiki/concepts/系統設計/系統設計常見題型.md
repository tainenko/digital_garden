# 系統設計常見題型

面試題目高度重複。按難度分類，掌握每類的核心挑戰，不同題目可以複用同樣的解題邏輯。

---

## 概念題（Concept-Based）

不設計系統，考核對特定概念的理解：

- API Gateway vs Load Balancer 的差別
- 如何設計 Rate Limiting（速率限制）
- SSO（單點登入）如何運作
- Kafka 的核心原理與使用場景
- 認證（Authentication）vs 授權（Authorization）

## 入門題（Easy）

### URL Shortener（短網址服務，如 TinyURL）
**核心挑戰**: 短碼生成（Hash vs 計數器）、高讀寫比、KV 存儲
**關鍵技術**: NoSQL KV（DynamoDB）、Cache（Redis）、一致性雜湊
**見**: [[RESHADED面試框架]] 中的完整範例

### 分散式快取（Distributed Cache）
**核心挑戰**: Cache eviction policy、一致性雜湊（節點增減時最小化 key 移動）
**關鍵技術**: Redis、Consistent Hashing

### CDN 設計
**核心挑戰**: Pull vs Push 模式、快取失效策略、地理路由

### 停車場系統（Parking Garage）
**核心挑戰**: 物件導向設計、狀態管理
**備注**: 偏 OOD（Object-Oriented Design），考場景建模

---

## 中級題（Medium）

### 社群媒體 Feed（Instagram / Twitter）
**核心挑戰**: Feed 生成策略（Push vs Pull vs 混合）
- **Push（Fanout on Write）**: 寫入時推送到所有 follower 的 Feed，讀取快但寫入慢、儲存多
- **Pull（Fanout on Read）**: 讀取時即時聚合，寫入輕但讀取慢
- **混合**: 一般用戶用 Push，大 V（高粉絲數）用 Pull
**關鍵技術**: Redis（Feed 快取）、Kafka（非同步 Fanout）、CDN（媒體）

### 即時聊天（WhatsApp / Messenger）
**核心挑戰**: 訊息送達保證、在線狀態、群組訊息擴散
**關鍵技術**: WebSocket、訊息佇列、NoSQL（訊息時序）

### 影片串流（YouTube / Netflix）
**核心挑戰**: 影片轉碼（多解析度）、CDN 分發、推薦系統
**關鍵技術**: Object Storage（S3）、CDN、轉碼任務佇列（Kafka）

### 音樂串流（Spotify）
**核心挑戰**: 授權管理、離線播放、歌詞同步

### 搜尋自動補全（Typeahead）
**核心挑戰**: Trie 資料結構、前綴快取、低延遲（<100ms）

### 訂票系統（Ticketmaster）
**核心挑戰**: 高並發搶票、超賣防止（Optimistic Locking / Queue）、票種庫存

---

## 進階題（Hard）

### 叫車服務（Uber / Lyft）
**核心挑戰**: 地理位置索引（Geohash / Quadtree）、司機匹配算法、即時位置更新
**關鍵技術**: WebSocket（位置串流）、Redis Geo、Kafka

### 協作文件（Google Docs）
**核心挑戰**: 多人即時編輯衝突解決（Operational Transformation / CRDT）
**關鍵技術**: WebSocket、OT 算法

### 雲端儲存（Dropbox / Google Drive）
**核心挑戰**: 大檔案分塊上傳、版本控制、Sync 衝突解決
**關鍵技術**: Object Storage、分塊 Hash（去重）、Delta Sync

### 網路爬蟲（Distributed Web Crawler）
**核心挑戰**: URL 去重、爬取優先度、避免爬取禁止頁面、速率限制
**關鍵技術**: Bloom Filter（URL 去重）、優先佇列、分散式任務調度

## 準備策略

### 80/20 原則
這三題打好底，可以解決 80% 的面試：
1. **URL Shortener** → 學 KV 存儲、Cache、一致性雜湊
2. **社群媒體 Feed** → 學 Fanout、NoSQL、CDN
3. **即時聊天** → 學 WebSocket、訊息佇列、狀態管理

### 練習方法（Aritra Sen 建議）
前5題：看完整解法再做
第6題起：先自己設計，再對照解法找差距
→ 每道題都要看多個來源，理解不同 trade-off
