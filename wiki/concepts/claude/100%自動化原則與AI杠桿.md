# 100% 自動化原則與 AI 杠桿

來自 [[Cat Wu]] 的核心觀點：AI 的杠桿效應只在達到 **100% 自動化**時才真正出現。95% 的準確率看似很高，實際上仍需人工審核，等同於沒有真正自動化。

> 「只有達到 100% 準確率的自動化流程才能產生真正的杠桿效應。95% 的準確率往往意味著它還不是真正的自動化。」

---

## 為什麼 95% 不夠

```
95% 準確率 → 100 次中有 5 次錯誤

選擇一：每次都人工審核 → 這不是自動化，只是「AI 輔助人工」
選擇二：不審核 → 每 20 次就有 1 次輸出錯誤的結果

結論：你仍然需要人的時間投入，只是換了一種形式
```

**真正的自動化** = 你可以完全信任它，不需要審核，直接使用輸出。

這才能「真正釋放你的時間」，讓你可以做其他事情。

---

## 95% → 100% 的投資值得嗎？

這是反直覺的一點：**最後的 5% 需要的時間，往往比前面 95% 更多**。

但只有完成這 5%，才能享受真正的杠桿效應：

```
                  你投入的工作量
                  ┌──────────────────────────────┐
                  │███████████████████░░░░░░░░░░│
                  └──────────────────────────────┘
                  0%                        100%
                         前 95%                 最後 5%

                  享受的杠桿效應
                  ┌──────────────────────────────┐
                  │                         ████│  ← 只有到這裡才真的省時間
                  └──────────────────────────────┘
```

Cat Wu 的建議：
> 「投入時間去規劃那些你真正想要實現 100% 自動化的任務，付出努力傳達你的偏好，提供反饋讓它提升技能達到 100%，這樣你才能真正信賴它。」

---

## 如何從 95% 走到 100%

### 第一步：明確「100% 的定義」

先問清楚：什麼樣的輸出算是 100% 成功？

```
❌ 模糊的成功定義：
「郵件分類做得不錯」

✅ 清晰的成功定義：
「所有來自我合作夥伴的郵件，準確率 100% 歸入 Partners 資料夾；
所有行銷和銷售推廣郵件，準確率 100% 歸入 Promotions；
沒有任何誤判會讓我錯過重要郵件」
```

### 第二步：找出失敗的邊緣案例

記錄每一次「這 5% 的錯誤」：

```
不要只說「分類錯了」，記錄：
- 這封郵件的特徵是什麼？
- 模型為什麼誤判？
- 下次要避免哪種情況？
```

### 第三步：系統性提供反饋

不是每次出錯都手動修正，而是讓反饋影響下一次的整體表現：

```
給 Claude（以 Gmail 分類為例）：
「你把來自 newsletter@anthropic.com 的郵件分到了 Promotions，
但我希望來自 anthropic.com 域名的所有郵件都進 Work 資料夾。
請更新你的分類規則，未來遇到類似情況都這樣處理。」
```

### 第四步：建立驗收測試

為你的自動化流程建立一個「回歸測試」：

```python
# 每次修改 Skill 或 Workflow 後，執行這個測試
test_cases = [
    {"input": "郵件A", "expected_folder": "Work"},
    {"input": "郵件B", "expected_folder": "Promotions"},
    # ... 你過去遇到過的所有邊緣案例
]
# 全部通過才算這個版本可以信任
```

## 如何找到值得自動化的任務

### 高價值自動化的三個特徵

1. **重複性高**：每週做超過 3 次的相同任務
2. **規則可描述**：你能用語言清楚說明「什麼是正確的輸出」
3. **錯誤代價低**：即使偶爾出錯，損失是可以接受的（不是核心決策）

### Cat Wu 的 CoWork 真實案例

**任務**：準備大型演講的簡報
- 連接數據源：Slack + Google Drive
- 描述輸出：「Anthropic 設計風格、20 頁、涵蓋 X 主題、不與主題演講重疊」
- CoWork 工作 1 小時，輸出設計水準的完整草稿
- 人類任務：一輪反饋（「文字太長，改精簡」）

**準確率評估**：~90%（還需一輪反饋），但對「簡報草稿」這個場景已經大幅節省時間。

### Applied AI 團隊的案例

**任務**：客戶會議前準備

```
連接：Salesforce + Gong + Slack
輸出：
- 這個客戶的需求是什麼？
- 過去的待辦事項有哪些？
- 他們最關心的問題是什麼？
- 最新的 ETA 信息？
```

從 20–30 分鐘手動準備 → 幾秒鐘自動生成。

## 過度定制的陷阱

Cat Wu 特別警告：追求 100% 自動化有一個反向的陷阱。

```
有兩種極端：

端 A：從不自動化任何事情 → 浪費時間在重複工作
     ↓ 應該改進

端 B：沉迷於定制工具本身
     - 添加大量 Skills
     - 研究各種 MCP 組合
     - 不斷優化工作流設定
     ↓ 但忘了最終目標是發布產品、交付功能
```

> 「我看到很多人在 Twitter 上說：快看我的配置，它已經失控了，它是如此優化。可你到底在構建什麼呢？」

**健康的做法**：簡單的配置 + 真實使用 → 遇到痛點再針對性優化 → 達到 100% 後不再動它。

---

## 人類的剩餘價值：定義「什麼是 100%」

即使達到了 100% 自動化，人類仍然有不可替代的角色：

**你是在定義「成功」的標準**，而不是執行標準。

```
AI 的任務：在你定義的標準內，100% 穩定執行

人類的任務：
- 決定哪些任務值得追求 100%
- 定義「100% 成功」的樣子
- 隨著情境變化，更新定義
- 把釋放出來的時間用於真正需要人類判斷的決策
```

> 「人類大腦的價值在於處理隱性知識、情商、常識，以及定義成功的『評測集』（Evals）。」
