# Redis 快取三大經典問題

快取層失效時如何保護後端資料庫，是後端與系統設計面試的高頻題。三者常被混淆，關鍵差異在「資料是否存在」與「過期 key 的數量」。

## 1. 快取雪崩（Cache Avalanche）
- **定義**：**大量 key 在同一時間集中過期**（或 Redis 整體當機），瞬間請求全部打到資料庫，導致 DB 過載甚至崩潰。
- **解法**：
  - 過期時間**加隨機值**（base + random），打散失效時點。
  - 快取**高可用**（Redis Cluster / 主從 + 哨兵），避免整體宕機。
  - 服務端**限流 / 降級 / 熔斷**作為兜底。
  - 多級快取（本地快取 + Redis）。

## 2. 快取穿透（Cache Penetration）
- **定義**：查詢**根本不存在的資料**（快取與資料庫都沒有），每次都繞過快取直查 DB；常被惡意攻擊利用（狂查不存在的 id）。
- **解法**：
  - **快取空值**：對查不到的 key 也寫入 null（設較短 TTL，如 30 秒）。
  - **布隆過濾器（Bloom Filter）**：在快取前擋一層，判斷 key「一定不存在」就直接拒絕，免打 DB。
  - 介面層參數校驗（過濾明顯非法的 id）。

## 3. 快取擊穿（Cache Breakdown）
- **定義**：**單一熱點 key 過期的瞬間**，大量併發請求同時打到 DB（與雪崩的差別：只是「一個」熱門 key，而非大量 key）。
- **解法**：
  - **互斥鎖（mutex）**：只讓一個請求去查 DB 並重建快取，其餘等待。
  - **熱點資料永不過期**（邏輯過期，後台非同步續期）。

## 速記對照
| 問題 | 資料存在？ | 範圍 | 核心解法 |
|------|-----------|------|---------|
| 雪崩 | 存在 | 大量 key 同時過期 | 隨機過期 + 高可用 |
| 穿透 | **不存在** | 持續查無效 key | 布隆過濾器 / 快取空值 |
| 擊穿 | 存在 | **單一熱點** key 過期 | 互斥鎖 / 永不過期 |
